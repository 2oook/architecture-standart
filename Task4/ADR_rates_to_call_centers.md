### <a name="_b7urdng99y53"></a>**Название задачи:** Передача актуальных ставок по депозитам в кол-центр банка и партнёрский кол-центр
### <a name="_hjk0fkfyohdk"></a>**Автор:** PILY, команда цифровой трансформации розничного бизнеса
### <a name="_uanumrh8zrui"></a>**Дата:** 21.11.2026

**Статус:** предложено. Решение дополняет ADR MVP онлайн-депозитов: [Task3/ADR_MVP_online_deposits.md](../Task3/ADR_MVP_online_deposits.md).

**Контекст.** Большинство клиентов банка — люди старшего возраста. После запуска маркетинговой кампании они начнут чаще звонить в кол-центр, чтобы уточнить условия депозита. Сейчас у операторов нет актуальных ставок: ставки считаются в Excel и рассылаются по почте только бэк-офису.

Банк хочет:
- дать операторам своего кол-центра актуальные ставки в их системе;
- подключить партнёрский кол-центр на случай перегрузки и тоже дать ему актуальные ставки.

Система партнёра — внешняя. Партнёр не может вызывать API, но готов получать ставки файлами, например по SFTP.

Решение опирается на текущий процесс работы со ставками после MVP. Ставки рассчитываются и утверждаются в модуле ставок АБС. Адаптер АБС публикует их в топик Kafka `deposit.rates.published`. Сайт и интернет-банк уже читают этот топик.

### <a name="_qmphm5d6rvi3"></a>**Решение**

#### Диаграммы

- Диаграмма контекста: [C4_Context_rates_to_call_centers.drawio](C4_Context_rates_to_call_centers.drawio).
- Диаграмма компонентов: [C4_Component_rates_to_call_centers.drawio](C4_Component_rates_to_call_centers.drawio).

На диаграммах показаны только элементы, которые важны для этого кейса. Сайт и интернет-банк не показаны. Они тоже читают топик ставок, но в этом кейсе не меняются.

#### Ключевые решения

1. **Единый источник ставок — модуль ставок АБС из MVP.** Кол-центр банка, партнёр, сайт и интернет-банк получают один и тот же снимок ставок. Поэтому клиент слышит по телефону ту же ставку, что видит на сайте. Рассылка ставок в Excel по почте отключается после запуска (задача T34).
2. **Событие ставок расширяется.** В событие `deposit.rates.published` добавляются признак публичной ставки, условия продукта (срок, минимальная сумма, капитализация, пополнение, частичное снятие), дата начала действия и номер версии. Событие содержит полный снимок, а не изменения. Поэтому любой получатель восстанавливает актуальное состояние по одному последнему сообщению. Все снимки публикуются с одним ключом `deposit-rates`, а для топика включена компакция. Поэтому Kafka всегда хранит последний снимок.
3. **Кол-центр банка получает ставки по событию.** Новый модуль «Ставки» в системе кол-центра — это Spring Boot-микросервис, который подключается через механизм расширения платформы. Компоненты модуля:
   - Kafka-слушатель;
   - сервис ставок;
   - репозиторий;
   - новая схема `rates` в PostgreSQL системы кол-центра;
   - REST API;
   - React-виджет в рабочем месте оператора.

   Стек совпадает со стеком платформы. Модуль могут сделать команда сопровождения подрядчика или Java-специалисты команды АБС. Модуль хранит ставки у себя, поэтому виджет работает даже при недоступности Kafka (NFR3).
4. **Партнёр получает ставки файлом через SFTP-сервер банка (pull-модель).** Новый сервис файлового обмена на Java 17 и Spring Boot формирует CSV-файл и выкладывает его на SFTP-сервер в DMZ банка. Партнёр сам забирает файл по расписанию. Банк при этом:
   - не хранит учётные данные от систем партнёра;
   - контролирует доступ к файлам и журнал скачиваний;
   - не зависит от доступности SFTP-сервера партнёра в момент выгрузки.

   Сервис файлового обмена относится к интеграционной платформе. Его разрабатывает команда АБС, потому что у неё есть Java-специалисты и опыт с адаптером.
5. **Отдельный сервис файлового обмена, а не выгрузка из АБС.** Выгрузка из PL/SQL (`UTL_FILE`) нагрузила бы перегруженную БД АБС и связала бы АБС с внешним партнёром. Отдельный сервис можно переиспользовать для других партнёров и других файлов, например скриптов звонков или кредитных ставок.
6. **Надёжность и контроль.** Планировщик с блокировкой ShedLock гарантирует, что файл формирует только один экземпляр. Журнал выгрузок хранится в MS SQL. Монитор доставки и система мониторинга сообщают о сбоях. API администрирования позволяет перезапустить выгрузку вручную.

#### Формат файла для партнёра (версия 1)

- Имя файла: `standart_deposit_rates_v1_<ГГГГММДДTЧЧММ>_<версия снимка>.csv` и рядом файл `.sha256`.
- Кодировка UTF-8, разделитель `;`, первая строка — заголовок, десятичный разделитель — точка.
- Колонки: `format_version; snapshot_version; published_at; effective_from; product_code; product_name; currency; term_days; min_amount; max_amount; rate_percent; capitalization; replenishment; partial_withdrawal; channel_note`.
- Файлы хранятся на SFTP 30 дней. Партнёр берёт файл с наибольшей версией снимка.

Пример строки:

```
1;20270315-001;2027-03-15T07:30:00+03:00;2027-03-15;DEP_STD_12;Стандарт 12 месяцев;RUB;365;10000;;16.50;monthly;yes;no;Ставка для открытия в отделении и интернет-банке
```

| Источник | Получатель | Протокол | Данные |
| :- | :- | :- | :- |
| БД АБС (Outbox) | Адаптер АБС | JDBC | Утверждённый снимок ставок |
| Адаптер АБС | Kafka | `deposit.rates.published`, TLS + SASL | Снимок ставок, версия, условия, признак публичности |

| Сервис файлового обмена | SFTP-сервер (DMZ) | SFTP, SSH-ключ | CSV-файл и `.sha256` |

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

| № | Альтернатива | Почему отклонена |
| :-: | :- | :- |
| A1 | Система кол-центра запрашивает ставки у сервиса ставок интернет-банка по REST | Вариант рабочий, но он связывает систему кол-центра с интернет-банком. Без собственного хранилища операторы теряют ставки при сбое интернет-банка. Kafka уже содержит нужные данные, и подписка не требует изменений в интернет-банке. |
| A2 | Отправлять партнёру Excel-файл по электронной почте, как сейчас внутри банка | Ручной процесс, нет контроля доставки и целостности. Почта не подходит для регулярного обмена с внешней компанией по требованиям безопасности. Ошибка сотрудника приведёт к неверным ставкам. |
| A3 | Push-модель: банк загружает файл на SFTP-сервер партнёра | Банку пришлось бы хранить учётные данные от инфраструктуры партнёра. Выгрузка зависела бы от доступности сервера партнёра. Вариант можно включить, если партнёр не сможет забирать файлы сам. Публикатор поддерживает оба режима. |
| A4 | Формировать файл в АБС процедурой PL/SQL (`UTL_FILE`) | Дополнительная нагрузка на перегруженную БД АБС. АБС напрямую связывается с внешним партнёром. Мониторинг и повторы пришлось бы писать на PL/SQL. |
| A5 | Дать операторам партнёра учётные записи в системе кол-центра банка | Нужны лицензии платформы подрядчика и доступ внешних сотрудников во внутреннюю систему банка. Растут риски информационной безопасности. Вариант можно рассмотреть, если партнёр станет постоянным. |
| A6 | Публиковать ставки партнёру только раз в день | Ставки могут измениться в течение дня. Партнёр консультировал бы по устаревшим ставкам до следующего утра. Выгрузка по событию с ежедневным контрольным файлом закрывает оба случая. |
| A7 | Отправлять в событии только изменения ставок | Получатель, который пропустил событие, получит неполные данные. Полный снимок небольшой (десятки продуктов) и упрощает восстановление после сбоя. |

**Недостатки, ограничения, риски**

| № | Недостаток, ограничение или риск | Как снижаем |
| :-: | :- | :- |
| R1 | Партнёр забирает файл по своему расписанию. Между публикацией и загрузкой у партнёра может пройти до 15–30 минут. | В регламенте фиксируется частота опроса. Монитор доставки проверяет, что файл забран. Каждый файл содержит время публикации, и оператор партнёра видит актуальность ставок. |
| R2 | Банк не контролирует загрузку файла в системе партнёра и то, как ставки показываются операторам. | Регламент обмена, тестовый обмен перед запуском (T31), обратная связь от бизнес-представителя. |
| R3 | SFTP-сервер в DMZ — новая точка входа из внешней сети. | Доступ только по ключу и с разрешённых IP, только чтение, отдельный каталог, журнал доступа, проверка безопасности перед запуском. |
| R4 | Доработка системы кол-центра зависит от подрядчика или от загрузки Java-специалистов команды АБС. В те же сроки идёт модуль лидов (T28). | Оба модуля делает одна команда в одном релизе. Объём согласуется с подрядчиком заранее. |
| R5 | Изменение формата файла может сломать загрузку у партнёра. | Версия формата в имени файла и в данных, параллельная выгрузка двух версий в переходный период (UC7). |
| R6 | Если АБС не опубликует ставки, все каналы покажут устаревшие ставки. | Ежедневная контрольная публикация, алерт при отсутствии новой версии до 07:45, отметка об устаревании в виджете. |
| R7 | Растёт число сервисов, которые нужно сопровождать. | Сервис файлового обмена использует тот же стек и шаблоны, что и адаптер АБС. Его можно переиспользовать для других партнёров. |
| R8 | Ставки в файле — коммерческая информация до её публикации на сайте. | Файл содержит только публичные ставки, которые уже действуют. С партнёром подписывается соглашение о конфиденциальности. |
