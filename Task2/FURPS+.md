# FURPS+: MVP онлайн-подачи заявок на депозит (сайт и интернет-банк)

Требования собраны из описания задания и IT-ландшафта банка «Стандарт».
Архитектурно значимые требования (АЗТ) отмечены **жирным**.
Дополнительные требования, которых нет в исходных данных, отмечены пометкой «(доп.)». Обоснование для них указано в комментарии.

| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1  | **Сайт показывает список доступных депозитов и накопительных счетов с актуальными ставками.** | Ставки сейчас есть только в XLS-файлах. Нужен единый источник ставок, доступный сайту без обращения к АБС в реальном времени. |
| F2  | **На сайте новый клиент подаёт заявку на депозит: ФИО, номер телефона, выбранный продукт.** | Заявка с сайта не создаёт депозит. Она создаёт задачу на звонок в системе кол-центра. |
| F3  | **Заявка с сайта попадает в систему кол-центра. Оператор видит её в очереди, звонит клиенту и фиксирует результат звонка.** | Система КЦ — платформа подрядчика на Java Spring Boot. Её можно расширять. Доработку могут выполнить Java-специалисты команды АБС или команда подрядчика. |
| F4  | Оператор кол-центра может предложить клиенту особые условия. Для этого он создаёт обращение в АБС, а бэк-офис депозитов определяет ставку. | В MVP используется текущий процесс обработки обращений из КЦ. Клиент получает СМС о ставке. |
| F5  | После звонка новый клиент приходит в отделение для идентификации. Депозит открывает сотрудник отделения. | Банк не принимает новых клиентов без личной проверки документов (115-ФЗ). Онлайн-открытие доступно только действующим клиентам интернет-банка. |
| F6  | **Интернет-банк показывает список депозитов и накопительных счетов с общими ставками и персональными ставками клиента.** | Персональная ставка зависит от остатков клиента и уровня кредитного риска банка. Её рассчитывает АБС, потому что только АБС хранит остатки. |
| F7  | **В интернет-банке клиент подаёт заявку на открытие депозита или накопительного счёта. Он выбирает продукт, счёт списания и сумму.** | Интерфейс проверяет сумму: минимальную и максимальную сумму продукта и остаток на счёте списания. |
| F8  | **Клиент подтверждает заявку одноразовым СМС-кодом (OTP).** | СМС-функционал находится в ядре платформы подрядчика. Доработку ядра нужно избежать. Отправку кода реализует команда банка в отдельном сервисе. |
| F9  | Клиент видит в интернет-банке статус заявки: «Подана», «Ставка подтверждена», «Депозит открыт», «Отклонена». | (доп.) Без статуса клиент будет звонить в кол-центр. Это увеличит нагрузку на операторов. |
| F10 | **Бэк-офис депозитов обрабатывает онлайн-заявку в АБС: подтверждает ставку и открывает депозит.** | Этап MVP. Заявки обрабатываются вручную по старому процессу, но поступают в АБС автоматически, без почты. |
| F11 | **Клиент получает СМС после подтверждения ставки и после открытия депозита.** | Уведомления отправляются по событиям смены статуса заявки. |
| F12 | **Ставки по депозитам ведутся в АБС вместо XLS-файлов. С ними работают бэк-офис депозитов и бэк-офис кредитов.** | Бэк-офис кредитов вводит базовые параметры: ставку ЦБ, уровень кредитного риска, надбавки. Бэк-офис депозитов видит рассчитанные ставки. |
| F13 | **Согласование специальной ставки по заявке идёт в АБС, а не по электронной почте.** | Бэк-офис кредитов передаёт в АБС только итоговую оценку риска по клиенту. Каждая сторона видит только свои данные. |
| F14 | **АБС публикует актуальные ставки и персональные предложения для внешних каналов: сайта, интернет-банка и в перспективе кол-центра.** | Публикация идёт при каждом изменении ставок и не реже одного раза в день. Каналы не обращаются к АБС за ставками напрямую. |
| F15 | (доп.) Повторная отправка заявки не создаёт дубликат. Каждая заявка имеет уникальный ключ идемпотентности. | Клиенты старшего возраста часто нажимают кнопку повторно. Сеть тоже может повторить запрос. Дубликат заявки приведёт к ошибке бэк-офиса. |
| F16 | (доп.) Форма на сайте защищена от ботов: CAPTCHA и ограничение частоты запросов. | Без защиты кол-центр получит поток ложных заявок. |
| F17 | (доп.) Система записывает в журнал аудита все действия с заявкой и ставками: кто, когда, что изменил. | Изменение ставок и условий депозита — финансово значимая операция. Банк обязан хранить след таких действий для внутреннего контроля и проверок ЦБ. |
| U   | Удобство использования (Usability) |              |
| U1  | **Интерфейсы сайта и интернет-банка соответствуют дизайн-системе банка: привычные цвета, шрифты, брендированные элементы.** | Требование бизнеса. Новые экраны используют общую библиотеку компонентов. |
| U2  | Заявка в интернет-банке оформляется не более чем за 3 шага: выбор продукта, параметры, подтверждение кодом. | (доп.) Короткий сценарий повышает конверсию. Это главная цель онлайн-канала. |
| U3  | (доп.) Интерфейсы учитывают клиентов старшего возраста: крупный шрифт, высокий контраст, простые формулировки. Ориентир — WCAG 2.1 уровня AA. | Основная аудитория банка — люди старшего возраста. Сложный интерфейс приведёт к звонкам в кол-центр. |
| U4  | (доп.) Сайт и интернет-банк корректно работают на мобильных устройствах (адаптивная вёрстка). | Банк хочет привлечь молодых клиентов. Они чаще пользуются смартфоном. |
| U5  | (доп.) Клиент может повторно запросить СМС-код через 60 секунд. Интерфейс показывает таймер и число оставшихся попыток. | СМС может прийти с задержкой. Без таймера клиент не поймёт, что делать дальше. |
| U6  | Сотрудники бэк-офиса видят ставки, онлайн-заявки и согласования в одном интерфейсе АБС, без Excel и почты. | Сокращает время обработки заявки и количество ошибок ручного переноса данных. |
| U7  | Оператор кол-центра видит заявку с сайта и её параметры в своей системе без переключения в другие приложения. | Снижает время обработки звонка. |
| R   | Надёжность (Reliability)           |              |
| R1  | **Все сервисы работают 24/7. Доступность — 99,9 % (не более 43 минут простоя в месяц).** | Требование бизнеса. Сейчас интернет-банк работает на одной группе серверов в одном ЦОД, поэтому требование пока невыполнимо. Решение должно это исправить. |
| R2  | **Интернет-банк и новые сервисы работают в двух ЦОД. При сбое одного ЦОД сервисы остаются доступны и выдерживают требуемую нагрузку.** | Резервный ЦОД сейчас подключается вручную. Нужно автоматическое переключение или режим active-active. |
| R3  | (доп.) Целевые показатели восстановления: RTO не более 15 минут, RPO = 0 для заявок. | Потеря поданной заявки — прямой ущерб репутации банка. RTO в 15 минут укладывается в бюджет простоя 99,9 %. |
| R4  | **Сбой или перегрузка АБС не останавливает приём заявок на сайте и в интернет-банке.** | Заявки накапливаются в очереди сообщений и передаются в АБС, когда она доступна. |
| R5  | **Сообщения доставляются гарантированно (at-least-once), а получатели обрабатывают их идемпотентно.** | Ни одна заявка и ни одна смена статуса не теряются. Повторная доставка не создаёт дубликатов. |
| R6  | (доп.) При недоступности АБС каналы показывают последние опубликованные ставки с датой их актуальности. | Ставки обновляются раз в день. Последний снимок ставок допустим для показа клиенту. |
| R7  | (доп.) Неудачная отправка СМС повторяется автоматически. Сообщения, которые не удалось обработать, попадают в отдельную очередь ошибок (DLQ) для разбора. | СМС-шлюз — внешняя зависимость. Клиент должен получить уведомление даже после временного сбоя шлюза. |
| R8  | (доп.) Все новые сервисы имеют мониторинг, алерты и сквозную трассировку запросов. | Без мониторинга нельзя подтвердить доступность 99,9 % и быстро найти причину сбоя в распределённой системе. |
| P   | Производительность (Performance)   |              |
| P1  | **Время отклика API ставок и списка продуктов — не более 100 мс (95-й перцентиль).** | Бизнес требует отклик в миллисекундах. Ставки меняются редко, поэтому их можно кешировать. |
| P2  | **Время отклика остальных операций интернет-банка (подача заявки, проверка кода, статус) — не более 300 мс (95-й перцентиль).** | Время доставки СМС в этот показатель не входит. |
| P3  | **Справочные данные кешируются. Загрузка справочников занимает не более 100 мс.** | Сейчас при проведении платежей некоторые справочные данные загружаются больше секунды. |
| P4  | **Новые сервисы масштабируются горизонтально. Запросы распределяются равномерно между серверами, экземплярами приложений и ЦОД.** | Требование IT. Масштабирование не должно требовать изменений в коде. |
| P5  | **Онлайн-каналы не создают синхронной нагрузки на БД АБС. Заявки передаются в АБС с ограничением скорости.** | БД АБС перегружена и масштабируется только вертикально. Прямая работа интернет-банка с API АБС в новом процессе запрещена. |
| P6  | (доп.) Система выдерживает пиковую нагрузку в 10 раз выше средней без деградации времени отклика. | Маркетинговая кампания вызовет всплеск посещений. Точные цифры нагрузки нужно уточнить у бизнеса. |
| P7  | (доп.) СМС-код доставляется клиенту не позднее 30 секунд после запроса. Код действует 5 минут. | Иначе клиент не успеет подтвердить заявку и бросит оформление. |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | **Новый функционал открытия депозитов реализуется отдельными микросервисами вне монолита интернет-банка.** | Это первый шаг перехода интернет-банка на микросервисную архитектуру. В MVP он затрагивает только открытие депозитов. |
| S2  | **Доработки не затрагивают ядро платформы интернет-банка, которое обновляет подрядчик.** | Изменения ядра зависят от подрядчика. Они увеличивают сроки и стоимость. |
| S3  | **Готовится документация для дальнейшего расширения: OpenAPI для REST API, AsyncAPI и схемы сообщений для Kafka, ADR для архитектурных решений.** | Следующий этап — заявки на кредиты на сайте и в интернет-банке. Он должен переиспользовать интеграции MVP. |
| S4  | (доп.) API и схемы событий версионируются. Новые версии обратно совместимы. | Сайт, интернет-банк, АБС и система КЦ обновляются разными командами в разное время. |
| S5  | (доп.) Новые сервисы собираются и разворачиваются через CI/CD с автотестами. Сервисы работают в контейнерах. | Без автоматизации нельзя часто и безопасно выпускать изменения в нескольких ЦОД. |
| S6  | (доп.) Продуктовая модель расширяется без изменения кода: новый продукт (депозит, накопительный счёт, позже кредит) задаётся параметрами. | Банк планирует добавить кредиты. |
| S7  | (доп.) Логи всех сервисов собираются централизованно. Каждый запрос имеет сквозной идентификатор. | Упрощает поиск ошибок в цепочке «интернет-банк — Kafka — АБС». |
| +R  | + Ограничения (Restrictions)       |              |
| +R1 | **Используются технологии, которые уже есть в банке: .NET (C#), Java, PHP, React.js, MS SQL, Oracle, PostgreSQL. Новые технологии должны быть совместимы с ними, а у сотрудников банка должна быть экспертиза хотя бы на уровне языка программирования.** | Требование IT. Новые сервисы интернет-банка пишутся на .NET, адаптер АБС — на Java. |
| +R2 | **Для очередей сообщений используется Apache Kafka.** | Требование IT на перспективу. |
| +R3 | **Текущая платформа интернет-банка (.NET Framework 4.5, ASP.NET MVC 4.5) несовместима с Kafka.** | Интеграция с Kafka выполняется через новые сервисы на современной .NET, а не из монолита. |
| +R4 | **Интернет-банк не работает напрямую с API и БД АБС в новом процессе.** | Требование команды АБС из-за перегрузки БД. Существующая интеграция для платежей остаётся без изменений. |
| +R5 | **АБС масштабируется только вертикально.** | Ограничение БД АБС. Решение должно ограничивать нагрузку на неё. |
| +R6 | **Трафик сайта и интернет-банка шифруется: TLS 1.2 и выше. Межсервисный трафик и Kafka тоже шифруются (mTLS, TLS + SASL).** | Сайт и интернет-банк передают персональные данные. |
| +R7 | **Сотрудники бэк-офиса депозитов и бэк-офиса кредитов не имеют доступа к данным друг друга.** | Требование безопасности. Ролевая модель в АБС разграничивает доступ к ставкам, рискам и заявкам. |
| +R8 | (доп.) Обработка персональных данных соответствует 152-ФЗ: согласие клиента на сайте, хранение в РФ, минимум собираемых данных. | Сайт собирает ФИО и телефон. Без согласия банк нарушит закон. |
| +R9 | (доп.) Информационная безопасность соответствует ГОСТ Р 57580.1 и требованиям ЦБ. Новые компоненты проходят проверку безопасности перед запуском. | Банк — финансовая организация. ЦБ проверяет выполнение этих требований. |
| +R10 | Новый клиент проходит идентификацию только в отделении. | 115-ФЗ запрещает принимать нового клиента без личной проверки документов. |
| +R11 | **Срок MVP — 6 месяцев. В MVP заявки обрабатывает бэк-офис вручную.** | Полностью автоматическое открытие депозитов — цель следующего этапа (через год). |
| +R12 | Система КЦ дорабатывается только через механизмы расширения платформы подрядчика. | Платформу полностью поддерживает подрядчик. Изменение ядра нарушит поддержку. |
| +R13 | Интернет-банк сейчас работает в одном ЦОД. Резервный ЦОД есть, но переключение на него ручное. | Это ограничение нужно снять, чтобы выполнить R1 и R2. |
